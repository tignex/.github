# Support

## Where to ask

**Use the project's own repository.** Questions about CommitBrief belong in
[CommitBrief](https://github.com/CommitBrief), BabelQueue in
[BabelQueue](https://github.com/BabelQueue), QueryProxy in
[QueryProxy](https://github.com/QueryProxy). Each project has its own
maintainers, its own documentation and its own issue tracker; a question in the
right place is answered by the person who wrote the code.

## Read first

Every project has documentation, and it is kept current on purpose:

- **CommitBrief** — [commitbrief.com/docs](https://commitbrief.com/docs/)
- **BabelQueue** — [babelqueue.com/docs](https://babelqueue.com/docs/) and the
  [specification](https://babelqueue.com/docs/spec/1.x/introduction/)
- **QueryProxy** — [queryproxy.com/docs](https://queryproxy.com/docs/)

The [engineering notes](https://tignex.com/notes/) cover the reasoning behind
decisions that surprise people, which is often the faster answer.

## Filing a good issue

An issue that can be reproduced is an issue that gets fixed. Include the version
you are running, the exact command or call, what you expected, what happened,
and the error text verbatim rather than paraphrased. Redact secrets — tokens,
connection strings, customer data — before pasting anything.

## Security

Do not open a public issue for a vulnerability. See the
[security policy](SECURITY.md).

## What is not supported

There is no paid support tier, no service level agreement and no hosted version
of any of these projects to escalate to. Everything runs on infrastructure you
control, which means the trade is real: you own the operation, and in exchange
nothing here depends on someone else staying in business.
